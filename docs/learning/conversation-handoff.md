## 当前能力及边界

- 运行内容全部位于 src，支持独立复制启动；冻结 PCOL 不进入交付构建。
- 已有 Practice、三档 AI、同机双人及本机联网房间闭环，四套正式场馆可同页切换。
- 房间由 Node 权威结算，浏览器显示运动轨迹。当前是单进程同步计算；内存状态不支持服务重启恢复。
- 创建、加入、准备、开局、比分、结果、双方重赛及刷新恢复均已有实现与专项；真实域名、公网和跨设备尚未验收。
- 单方长期离线尚无自动结束策略；两席都离线超过宽限后才清理。
- 架构和功能回归通过不代表游戏体验流畅。当前用户明确反馈不够流畅，后续必须以实际操作及帧耗时测量验证改善。

## 工程整理

结构和命名校验统一归 tooling/validation；tooling/lib 只放跨职责基础工具。四个命令编排入口共用 run-node，避免重复维护子进程状态、工作目录与 Windows 窗口行为。scripts 保持用户入口，不另引入任务框架。

浏览器与 Node 的工厂实例化逻辑已归 runtime/factory-loader，各实例缓存仍独立；浏览器传输与服务端文件读取保持各自职责。菜单的房间请求与比赛交接归 room-menu-controller，本地场馆、抽屉及 UI 生命周期归 interior-menu-controller。

运行模块的拆合以依赖、状态所有权和生命周期为依据，不能按文件长度或数量机械合并。具名模块、第三方工厂 ABI、src 独立启动和冻结基准是当前维护契约。详细约束见[组合根边界](../architecture/composition-root-assessment.md)。

本轮整体浏览器检查、202 项单元/集成、同机 24 组合及两场景生命周期、src 独立复制启动和默认连续运行均已通过。连续专项包含 Chrome/Edge 的冻结/开发版本各 18 杆 Practice、三档 AI、回放和重开。输入哈希、范围与限制见[运行层整理记录](../../reports/validation/runtime-cleanup.json)，不代表帧耗时改善。

## 本机帧耗时基线

2026-11-14 已完成真实操作、三轮当前配置GPU、启动与场馆切换、回环联网结算测量。常态约60Hz仍有51–103ms偶发长任务；GPU未显示持续超预算；缓存场景约25–32ms准备完成，但菜单可操作仍需约467–476ms。下一步优先核对UI交接与入场等待链。详见[基线与限制](../validation/frame-time-baseline.md)，本轮没有修改运行参数或宣称卡顿已解决。

## 入场与焦点优化

基线后已实施：抽屉返回菜单160ms、首页相机最多600ms、本地比赛相机最多450ms，并修复延迟默认聚焦抢输入的竞态。205项单元/集成、整体浏览器、室内六套、同机24组合、生命周期、抽屉和独立启动通过。本机缓存切换中位约281ms，Practice入场约983ms，详见[优化及trace结果](../validation/entry-optimization.md)。

六次时间对齐trace没有稳定复现旧操作期长任务，但定位到启动模型完成回调中的1.09–1.96秒同步任务及部分GPU命令等待。下一步应细化模型/材质/HDR初始化与就绪查询，不能把这些时间归为纯下载或直接改写物理。
